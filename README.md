# ☕ باشگاه مشتریان کافه

## دریافت فایل کامل برای کپی در Cloudflare

**[باز کردن فایل کامل Worker (متنی)](deliverables/worker-complete.txt)** — در صفحهٔ فایل، روی **Raw** یا **Download raw file** بزنید. این فایل همهٔ کد لازم، از جمله اصلاح ورود، را دارد؛ نه فقط `src/index.ts`.

نسخهٔ فعلی **`site-recovery-v4`** است: فرم ورود بدون هدایت اجباری نشست قبلی، بررسی کامل‌تر ساختار DB، ارتقای افزایشی از مرورگر با پشتیبان و تأیید مدیر، و رفع خطای اصلاح فاکتور. راهنمای فعلی: [RECOVERY-FA.md](RECOVERY-FA.md). بعد از Deploy، `data.build` در `/api/health` باید همین مقدار باشد.

این نسخهٔ تحویلی عمداً در Git ثبت شده تا بدون پیوست چت هم در دسترس باشد. جزئیات ساخت و نسخه: [deliverables/README.md](deliverables/README.md).


وب‌اپلیکیشن کامل باشگاه مشتریان برای کافه — **۱۰۰٪ روی زیرساخت Cloudflare**:

| لایه | فناوری |
| --- | --- |
| Runtime | Cloudflare Workers (Serverless) |
| Backend | [Hono](https://hono.dev) |
| Database | Cloudflare D1 (SQLite) |
| Frontend | HTML + Tailwind CSS (CDN) + Vanilla JS |
| Auth | JWT با `hono/jwt` + کوکی HttpOnly |

بدون بیلد استپ پیچیده، بدون سرور، بدون هزینه‌ی زیرساخت اضافه.

## ارتقای ثبت فاکتور و پیام‌های ادمین

- سه سیاست ادمین: نسبت مبلغ، یک‌بار در روز تهران، یا امتیاز ثابت برای هر فاکتور مثبت.
- منوی حداکثر ۱۰۰۰ آیتم، دسته‌ها/پرفروش‌ها در شروع و ورود دستی نام/قیمت/تعداد.
- گزارش عملیات مستقل از سلامت sms.ir، روی همان اتصال رمز‌شدهٔ تلگرام/بله؛ تاریخچه و retry آگاهانه.
- ذخیرهٔ اتمیک تنظیمات و رسید اصلاح از موجودی نهایی، بدون تغییر schema در این ارتقا.

**فایل تک‌فایل، اعمال روی سایت موجود، فایل‌های تغییرکرده، تست‌ها و محدودیت‌ها: [UPGRADE-FA.md](UPGRADE-FA.md).**

## ✨ قابلیت‌ها

### پورتال مشتری
- ثبت‌نام با نام، شماره موبایل، **تاریخ تولد شمسی** و کد معرف اختیاری
- کارت عضویت دیجیتال با کد معرف اختصاصی و لینک دعوت
- اعتبارسنجی سمت سرور برای شماره، تاریخ تولد و کد معرف
- محافظت ضد اسپم (Rate Limit) روی ثبت‌نام

### پنل کارمند (`/staff`)
- جستجوی مشتری با شماره موبایل (نوتیفیکیشن «مشتری یافت نشد» + لینک ثبت‌نام)
- **جستجوی زندهٔ محصول** با کلید `/` + چیپ «پرکاربردترین‌ها» (از سابقهٔ ۳۰۰ فاکتور آخر)
- انتخاب آیتم از منوی کافه + تعداد (یا ورود مبلغ دستی)
- محاسبه‌ی خودکار مبلغ، تخفیف، امتیاز و **باقیماندهٔ پول**
- **روش پرداخت:** نقدی / کارت‌خوان / آنلاین / **ترکیبی** با کنترل دقیق مبالغ سمت سرور
- `Ctrl+Enter` برای ثبت فاکتور، `Esc` بستن رسید
- نمایش رسید با روش پرداخت و باقیمانده، ارسال پیامک تأیید
- آمار فاکتورهای امروز + تاریخچهٔ **جستجوپذیر** فاکتورهای کارمند (نام، موبایل، شماره، نام محصول)

### صندوق و شیفت (`/staff/shift`، `/admin/shifts`)
- باز کردن صندوق با موجودی اولیه (یک صندوق باز برای هر صندوق‌دار)
- ثبت **ورود/خروج نقد** با توضیح
- محاسبهٔ زندهٔ «نقد مورد انتظار» = اولیه + فروش نقدی معتبر + ورود − خروج
- بستن صندوق با **مبلغ شمارش‌شده**، نمایش اختلاف، ثبت یادداشت
- گزارش هر شیفت: تفکیک نقد/کارت/آنلاین، تعداد فاکتور، ابطال‌ها، گردش نقد، فاکتورهای همان شیفت
- تنظیم اختیاری «الزام باز بودن صندوق برای ثبت پرداخت نقدی»

### داشبورد ادمین (`/admin`)
- **نمای کلی:** کل مشتریان، فروش امروز، فروش ماه شمسی، مشتریان در خطر ریزش
- نمودار فروش ۷ روز، مشتریان برتر، آخرین فاکتورها
- **مدیریت مشتریان:** جستجو، فیلتر سطح/وضعیت، صفحه‌بندی، خروجی CSV
- **جزئیات مشتری:** ویرایش اطلاعات، تنظیم دستی امتیاز، فاکتورها، کدهای تخفیف، شبکه‌ی معرفی
- **تنظیمات:** قالب ۵ پیامک، نسبت امتیازدهی، سطح‌بندی، آستانه‌های ریزش، درصد تخفیف تولد، منوی کافه، کلیدهای API
- **مدیریت کارمندان:** ساخت/غیرفعال‌سازی/حذف، تغییر رمز، تغییر نقش (با محافظت از آخرین ادمین)
- **لاگ پیامک‌ها:** فیلتر بر اساس نوع و وضعیت
- **کدهای تخفیف:** ساخت کد عمومی یا اختصاصی، مدیریت انقضا
- **فاکتورها:** جستجو (نام مشتری، موبایل، شماره، **نام محصول**، ارقام فارسی)، فیلتر روش پرداخت/وضعیت/صندوق‌دار/بازهٔ شمسی، پنجرهٔ جزئیات، **ابطال با دلیل** و **اصلاح فاکتور** (فاکتور جدید جایگزین + بایگانی اصلی)
- **گزارش‌ها:** فروش امروز/دیروز/۷ روز/۳۰ روز/هفتگی/ماهانه، تعداد و میانگین فاکتور، تخفیف، ابطال، تفکیک روش پرداخت، پرفروش‌ترین بر اساس تعداد و مبلغ، عملکرد صندوق‌دار، مقایسهٔ دوره‌ها
- اجرای دستی جاب‌ها برای تست

### جاب‌های خودکار (Cron)
| جاب | زمان (تهران) | توضیح |
| --- | --- | --- |
| پیش‌بینی ریزش | ۲۳:۰۰ هر شب | مشتریانی که بیش از «میانگین فاصله خرید + مهلت» نیامده‌اند پیامک «دلتنگیم» می‌گیرند (با کول‌داون ۳۰ روزه) |
| تولد | ۰۸:۰۰ هر روز | تبریک تولد + کد تخفیف اختصاصی ۱۴ روزه (یک‌بار در سال) |
| آب‌وهوا | ۰۸:۳۰ هر روز | وضعیت هوای شهر از OpenWeather و پیامک مناسب (بارانی/آفتابی/برفی…) |
| نگهداری | هر ساعت | بازمحاسبه میانگین خرید، انقضای کدها، پاک‌سازی لاگ‌های قدیمی |
| گزارش ماهانه | اول هر ماه | خلاصه‌ی عملکرد برای ادمین‌ها |

> جاب‌ها هر بار حداکثر ۵۰ پیامک می‌فرستند تا از سقف Subrequest پلن رایگان عبور نکنیم.

### سیستم معرفی
- هر مشتری یک کد یکتا مثل `REF-A1B2C3` دارد
- هنگام ثبت‌نام، کد معرف (یا شماره معرف) اعتبارسنجی می‌شود
- پس از **اولین فاکتور** مشتری معرفی‌شده، امتیاز پاداش به معرف اضافه می‌شود (یک‌بار)

## ☁️ دیپلوی روی Cloudflare

### ۰) دریافت پروژه و رفتن به پوشهٔ درست

> ⚠️ **مهم‌ترین نکته:** هر دو خطای رایج
> `Unable to read SQL text file "schema.sql"` و
> `Required Worker name missing`
> یعنی دستور از **پوشهٔ اشتباه** اجرا شده است؛ یعنی `wrangler.toml` و `schema.sql` در پوشهٔ جاری نیستند.
> همیشه اول با `ls wrangler.toml schema.sql` مطمئن شوید که داخل ریشهٔ پروژه هستید.

```bash
git clone -b arena/ba9e1761-checklists https://github.com/boogh13822-spec/checklists.git cafe-club
cd cafe-club
npm install
```

### ۱) انتشار خودکار (ساده‌ترین راه) ⭐

یک اسکریپت آماده همهٔ مراحل زیر را انجام می‌دهد (ساخت D1، نوشتن `database_id`، اجرای schema، ساخت Secret و دیپلوی):

```bash
bash scripts/deploy.sh
```

### ۲) ساخت دیتابیس D1 (روش دستی)

```bash
npx wrangler login
npx wrangler d1 create cafe-club-db --location weur
```

خروجی یک `database_id` می‌دهد. آن را در `wrangler.toml` جای‌گذاری کنید:

```toml
[[d1_databases]]
binding = "DB"
database_name = "cafe-club-db"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

اگر شناسه را گم کردید:

```bash
npx wrangler d1 list --json
```

### ۳) ساخت جدول‌ها و داده‌های اولیه

```bash
npx wrangler d1 execute cafe-club-db --remote --file=./schema.sql
# یا: npm run db:init:remote
```

> `schema.sql` تکرارپذیر است (`IF NOT EXISTS` + `ON CONFLICT DO NOTHING`)؛ اجرای دوبارهٔ آن آسیبی نمی‌زند.

### ۴) تنظیم Secret

```bash
npx wrangler secret put JWT_SECRET     # مقدار را در ترمینال پیست کنید (حداقل ۳۲ کاراکتر)
```

ساخت مقدار تصادفی:

```bash
openssl rand -base64 48
```

### ۵) انتشار

```bash
npx wrangler deploy
# یا: npm run deploy
```

اگر باز هم `Required Worker name missing` دیدید، یعنی wrangler فایل کانفیگ را پیدا نکرده است؛ با مسیر صریح اجرا کنید:

```bash
npx wrangler deploy --config ./wrangler.toml
# یا با تعیین دستی نام:
npx wrangler deploy --name cafe-club --config ./wrangler.toml
```

### ۶) به‌روزرسانی نسخهٔ منتشرشده

وقتی نسخهٔ تازه‌ای از کد منتشر می‌شود، **دیتابیس و داده‌ها را دست نزنید**؛ فقط کد را جایگزین کنید:

```bash
cd cafe-club          # همان پوشه‌ای که wrangler.toml دارد
bash scripts/update.sh
```

این اسکریپت به‌ترتیب: `git pull` → `npm install` → بررسی TypeScript → ساخت بستهٔ تک‌فایلی → `wrangler deploy`.
**نه `schema.sql` را اجرا می‌کند و نه `JWT_SECRET` را عوض می‌کند**، پس مشتریان، امتیازها و نشست‌ها سالم می‌مانند.

معادل دستی همان کار:

```bash
cd cafe-club
git pull origin arena/ba9e1761-checklists
npm install
npx wrangler deploy
```

اگر از **Quick Edit** استفاده می‌کنید (پیست یک فایل):

```bash
npm run build:single      # ساخت single-file/worker.js
# سپس محتوای این فایل را کامل در ادیتور Cloudflare جای‌گذاری و Deploy کنید
```

> اگر تغییرات محلی خودتان را دارید، قبل از pull آن‌ها را نگه دارید: `git stash -u` … و بعد `git stash pop`.
> برای چرخش عمدی `JWT_SECRET` (باطل‌کردن همهٔ نشست‌ها): `ROTATE_SECRET=1 bash scripts/deploy.sh`.

### نجات حساب مدیر (اگر قفل شدید)

اگر رمز ادمین را فراموش کردید، حساب غیرفعال شد یا نقشش تغییر کرد:

```bash
bash scripts/rescue-admin.sh                          # شمارهٔ پیش‌فرض + رمز تصادفی
bash scripts/rescue-admin.sh 09121234567 'MyPass@1404' # شماره و رمز دلخواه
bash scripts/rescue-admin.sh 09120000000 'MyPass@1404' --local   # روی دیتابیس محلی
```

اسکریپت رمز را با همان الگوریتم اپ (PBKDF2-SHA256) می‌سازد، نقش را `admin` و حساب را فعال می‌کند، و اگر شماره وجود نداشته باشد حساب مدیر جدید می‌سازد.

### ۷) اتصال دامنه (اختیاری)

در داشبورد Cloudflare → Workers & Pages → `cafe-club` → Settings → Domains & Routes، دامنه‌ی خود را اضافه کنید.

## 🔑 متغیرها و Secretها

| نام | نوع | الزام | توضیح |
| --- | --- | --- | --- |
| `JWT_SECRET` | Secret | **الزامی** | امضای توکن JWT؛ حداقل ۳۲ کاراکتر |

## 📱 سرویس پیامک (sms.ir)

به صورت پیش‌فرض روی حالت `console` است: پیام‌ها فقط در لاگ Worker و جدول `sms_logs` ثبت می‌شوند — بدون هزینه و مناسب توسعه.

### اتصال به sms.ir (پیشنهادی)

1. وارد پنل [sms.ir](https://sms.ir) شوید.
2. از بخش **وب‌سرویس / API** کلید API (API Key) خود را کپی کنید.
3. **شماره خط** (LineNumber) را از پنل بردارید — همان شماره‌ای که پیامک با آن ارسال می‌شود و فقط عدد است (مثلاً `30007732000000`).
4. در اپلیکیشن: **داشبورد → تنظیمات → اتصال سرویس‌ها**
   - سرویس‌دهنده: **sms.ir (پیشنهادی)**
   - شماره خط فرستنده: همان LineNumber
   - کلید API: کلید کپی‌شده
   - ذخیره کنید.
5. دکمه‌ی **«پیامک آزمایشی به خودم»** را بزنید؛ نتیجه در `/admin/sms` ثبت می‌شود.
6. با دکمه‌ی **«اعتبار sms.ir»** می‌توانید موجودی حساب را ببینید.

نکات مهم:

- این اپلیکیشن از متد **ارسال گروهی** sms.ir استفاده می‌کند:
  `POST https://api.sms.ir/v1/send/bulk` با هدر `X-API-KEY`.
  هر پیامک یک درخواست جداگانه است (نه یک بسته‌ی چندنفره)، پس قالب‌های اختصاصی هر مشتری درست ارسال می‌شوند.
- اعتبار حساب با متد `GET https://api.sms.ir/v1/credit` خوانده می‌شود.
- کلید API بعد از ذخیره **دیگر در HTML صفحه نمایش داده نمی‌شود**؛ برای تغییر، مقدار جدید را وارد کنید و برای حذف، تیک «حذف کلید» را بزنید.
- اگر کلید یا شماره خط تنظیم نشده باشد، در جدول `sms_logs` خطای واضح ثبت می‌شود و هیچ پیامکی ارسال نمی‌گردد.
- برای امنیت بیشتر می‌توانید کلید را به‌جای دیتابیس، به‌صورت Secret تنظیم کنید:

```bash
npx wrangler secret put SMSIR_API_KEY
```

### کاوه‌نگار (جایگزین)

۱. در [کاوه‌نگار](https://kavenegar.com) کلید API بگیرید.
۲. در تنظیمات، سرویس‌دهنده را روی **کاوه‌نگار** بگذارید و کلید + شماره فرستنده را وارد کنید.
۳. «پیامک آزمایشی به خودم» را بزنید.

> برای اضافه‌کردن سرویس‌دهنده‌ی دیگر، توابع `sendViaSmsIr` / `sendViaKavenegar` در `src/lib/sms.ts` را الگو بگیرید.

## 🌤 سرویس هواشناسی

1. کلید رایگان از [OpenWeatherMap](https://openweathermap.org/api) بگیرید.
2. در تنظیمات → «کلید API هواشناسی» وارد کنید.
3. نام شهر را در «اطلاعات کافه» تنظیم کنید (مثلاً `Tehran`) و «تست آب‌وهوا» را بزنید.

اگر کلید تنظیم نشده باشد، جاب آب‌وهوا با پیام واضح رد می‌شود و بقیه‌ی برنامه بدون اختلال کار می‌کند.

**درباره‌ی «یک فایل»:** طبق درخواست، تمام فرانت‌اند داخل Template Literal است و هیچ فایل HTML/CSS/JS جدا یا بیلد استپ فرانتی وجود ندارد. نقطه‌ی ورود و دیپلوی تنها یک فایل است (`src/index.ts`)؛ Wrangler بقیه‌ی ماژول‌ها را خودکار باندل می‌کند. اگر واقعاً یک فایل تک‌نفره برای «پنل Quick Edit» کلادفلر می‌خواهید:

```bash
npm run build:single     # → single-file/worker.js  (یک فایل، بدون import)
```

سپس محتوای `single-file/worker.js` را در ویرایشگر Quick Edit کلادفلر جای‌گذاری کنید و Binding دیتابیس `DB` را وصل کنید.

## 🧮 قواعد کسب‌وکار

- **امتیاز:** `floor(مبلغ ÷ واحد مبلغ) × امتیاز هر واحد` — پیش‌فرض: هر ۱٬۰۰۰ تومان = ۱ امتیاز
- **سطح‌ها:** برنزی (شروع) → نقره‌ای ۵۰۰ → طلایی ۲٬۰۰۰ → الماسی ۵٬۰۰۰ (قابل تغییر)
- **میانگین فاصله خرید:** از روی روزهای متمایز خرید (تا ۱۰۰ فاکتور اخیر) محاسبه می‌شود
- **آستانه‌ی ریزش:** `روزهای غیبت > میانگین + مهلت` و حداقل `churn_min_visits` خرید
  - اگر مشتری فقط یک روز خرید کرده باشد (میانگین صفر)، مبنای سنجش ۳۰ روز است
  - هر مشتری حداکثر هر ۳۰ روز یک پیامک دلتنگی می‌گیرد
- **تولد:** مقایسه‌ی ماه/روز شمسی؛ کد تخفیف سالی یک‌بار صادر می‌شود
- **کد تخفیف:** درصدی یا مبلغی، اختصاصی یک مشتری یا عمومی، با سقف استفاده و انقضا
- **پاداش معرف:** فقط پس از اولین فاکتور مشتری معرفی‌شده و فقط یک‌بار

## 🔐 امنیت

- **رمز عبور:** PBKDF2-SHA256 با نمک تصادفی ۱۶ بایتی و ۲۵٬۰۰۰ دور (سازگار با محدودیت CPU پلن رایگان). هر هش، تعداد دور خودش را ذخیره می‌کند؛ بنابراین افزایش دورها در آینده بدون شکستن رمزهای قبلی ممکن است. برای پلن Paid می‌توانید `PBKDF2_ITERATIONS` در `src/lib/crypto.ts` را افزایش دهید.
- **JWT:** HS256، انقضای ۱۲ ساعته، کوکی `HttpOnly` + `SameSite=Lax` + `Secure` روی HTTPS
- **CSRF:** بررسی هم‌مبدأ بودن `Origin` برای همه‌ی درخواست‌های تغییردهنده + کوکی SameSite
- **XSS:** به‌صورت پیش‌فرض همه‌ی مقادیر با `escapeHtml` رندر می‌شوند؛ خروجی JSON در اسکریپت‌ها با escape امن تزریق می‌شود
- **SQL Injection:** تمام کوئری‌ها Prepared Statement با Binding هستند
- **دسترسی:** هر مسیر API با `requireApiRole` و هر صفحه با `requirePageRole` محافظت می‌شود؛ نقش و فعال‌بودن کاربر در هر درخواست از دیتابیس بازخوانی می‌شود تا غیرفعال‌سازی فوری اعمال شود
- **Rate Limit:** ورود ۸ تلاش / ۱۵ دقیقه، ثبت‌نام ۶ / ۱۰ دقیقه، API عمومی ۱۲۰ / دقیقه (در حافظه‌ی ایزوله — بهترین تلاش)
- **سرصفحه‌های امنیتی:** `nosniff`, `Referrer-Policy`, `Permissions-Policy`, `COOP`
- اعتبارسنجی و پاک‌سازی همه‌ی ورودی‌ها سمت سرور (نه فقط کلاینت)

> نکته: Rate Limit در حافظه‌ی هر ایزوله است. برای محدودسازی دقیق‌تر می‌توانید از Cloudflare WAF / Rate Limiting Rules استفاده کنید.

## 📬 ارسال جایگزین پیامک (تلگرام و بله)

در **تنظیمات ← ارسال جایگزین پیامک (Fallback)** می‌توانید یک یا هر دو پیام‌رسان را انتخاب کنید.
در نبود پنل فعال یا شکست ارسال اصلی، پیام شامل شمارهٔ مشترک، متن کامل، زمان شمسی و شناسهٔ کاربر
در صف پایدار D1 قرار می‌گیرد و در پس‌زمینه برای ادمین ارسال می‌شود؛ نه مستقیماً برای مشترک.
توکن‌ها و محتوای صف رمز می‌شوند. OTP نیز طبق تنظیم این نسخه پوشش داده می‌شود؛ فقط مقصد خصوصی انتخاب کنید.
تاریخچهٔ اختصاصی: `/admin/fallback`.

**راه‌اندازی Secret رمزنگاری، مایگریشن، نمونه‌های تلگرام/بله، تست و محدودیت‌های نرخ/OTP:**
[FALLBACK-FA.md](./FALLBACK-FA.md). انتشار کد به‌تنهایی برای فعال‌کردن این قابلیت کافی نیست.

## 🩺 عیب‌یابی

| مشکل | راه‌حل |
| --- | --- |
| `Unable to read SQL text file "schema.sql"` | دستور از پوشهٔ اشتباه اجرا شده؛ `cd` به ریشهٔ پروژه‌ای که `schema.sql` در آن است (`ls wrangler.toml schema.sql`) |
| `Required Worker name missing` | `wrangler.toml` در پوشهٔ جاری نیست؛ یا `npx wrangler deploy --config ./wrangler.toml` بزنید یا فایل را کنار دستور بیاورید |
| بعد از آپدیت، صفحه‌ها نسخهٔ قدیمی را نشان می‌دهند | `npx wrangler deployments list` را ببینید؛ اگر آخرین انتشار تازه است، کش مرورگر/سرویس‌ورکر را با `Ctrl+Shift+R` پاک کنید |
| `no such table: users` | `schema.sql` اجرا نشده؛ `npm run db:init:remote` |
| «کلید JWT تنظیم نشده است» | `npx wrangler secret put JWT_SECRET` (حداقل ۳۲ کاراکتر) |
| ورود با خطای CPU | لاگ و سقف CPU پلن را بررسی کنید؛ برای حل خطای CPU هزینهٔ هش رمز را کاهش ندهید؛ در صورت نیاز پلن/بودجهٔ CPU را ارتقا دهید |
| پیامک ارسال نمی‌شود | `/admin/sms` را ببینید؛ در sms.ir کلید API و «شماره خط» (LineNumber) را بررسی کنید. پیام خطا در ستون error ثبت می‌شود |
| `کلید API سامانه sms.ir نامعتبر است` | کلید را از پنل sms.ir دوباره کپی کنید (بدون فاصله) و ذخیره کنید |
| `شماره خط فرستنده (LineNumber) تنظیم نشده است` | شماره خط را فقط به‌صورت عدد در تنظیمات وارد کنید |
| `اتصال به sms.ir برقرار نشد` | کلید/خط را بررسی کنید؛ اگر در محیط محلی اجرا می‌کنید، دسترسی خروجی شبکه لازم است |
| آب‌وهوا کار نمی‌کند | کلید OpenWeather و نام شهر (انگلیسی) را بررسی کنید |
| جاب‌ها اجرا نمی‌شوند | Cron در `wrangler.toml` باید با `dispatchCron` هم‌خوان باشد؛ لاگ Worker در داشبورد |
| «ورود کامل نشد» در نسخهٔ قبلی | کل فایل `deliverables/worker-complete.txt` جدید را منتشر کنید؛ `/api/health` باید build برابر `site-recovery-v4` داشته باشد؛ راهنمای `RECOVERY-FA.md` |
| خطای 500 پیش از فرم ورود / ساختار قدیمی | نسخهٔ کامل تازه را منتشر کنید؛ فرم ورود با نشست قبلی هم باز است. مدیر در `/admin/system` بکاپ خصوصی را می‌گیرد و ارتقای افزایشی را تأیید می‌کند |
| خطای 503 خواندن حساب/نشست | اتصال، سهمیه و لاگ D1 را بررسی کنید؛ خطای DB به معنی مسدودبودن Cookie نیست و با بازنشانی رمز حل نمی‌شود |
| «نشست شما منقضی شده است» و برگشت به صفحهٔ ورود | اگر رمز اشتباه باشد پیام واقعی نمایش داده می‌شود؛ این پیام فقط وقتی است که کوکی نشست نامعتبر شده (مثلاً `JWT_SECRET` عوض شده). دوباره وارد شوید |
| وارد پنل نمی‌شوم / رمز ادمین را فراموش کرده‌ام | `bash scripts/rescue-admin.sh 0912xxxxxxx 'رمز-جدید'` — حساب را بازنشانی، فعال و نقش را `admin` می‌کند |
| «تلاش‌های ناموفق زیاد بوده است» | محدودیت ۸ تلاش در ۱۵ دقیقه؛ ۱۵ دقیقه صبر کنید یا از IP دیگر وارد شوید |
| فونت یا Tailwind لود نمی‌شود | دسترسی CDN از شبکه‌ی کاربر لازم است (برای محیط بسته، فایل‌ها را self-host کنید) |
